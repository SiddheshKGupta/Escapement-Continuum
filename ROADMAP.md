# Roadmap — superseded

The original roadmap sequenced work toward validating an architecture:
independent scoring of Experiment 001, then model integration, then
Experiment 002, then 003–005, then an MCP surface.

**That sequence is void.** It assumed a distinguishing architecture
existed. Phase I established that it does not.

```text
Step 0  independent scoring of 001    -> done 3x, all FAIL; 001 reclassified as C001
Step 1  decision journal              -> built; 12 entries, 0 resolved predictions
Step 2  Experiment 002                -> CANCELLED BEFORE EXECUTION
Step 3  model integration             -> void (nothing to integrate into)
Step 4  Experiments 003-005           -> void (all downstream of a dead thesis)
Step 5  MCP surface                   -> void
```

There is no roadmap now, because Continuum has no architecture to build
toward. Producing one would be the sunk-cost error the programme
explicitly rejects.

**Current agenda:** none. The programme is FROZEN — see the README.
The Phase II problem list is preserved at
[`docs/CONTINUUM_OPEN_PROBLEMS.md`](docs/CONTINUUM_OPEN_PROBLEMS.md);
it reopens only when Escapement Core meets a concrete problem that
deterministic mechanisms handle badly.

## What survives from the original standing rules

Two of the four were earned and carry forward into Phase II:

1. **No mechanism ships without an experiment that could falsify it.**
2. **Independent scoring for anything self-authored.** Four consecutive
   independent reviews found real defects in work its author had assessed
   as correct — including two announced fixes that were structurally
   inert, and a checker that passed the exact defect it was written to
   catch.

Two were superseded by stronger versions:

3. *"PARTIAL is a real verdict"* → generalised into the admission rule.
4. *"No claim outruns its evidence"* → generalised into the comparator
   and simplicity rules, which are stricter: the claim must now outrun
   **v1 plus the smallest reasonable enhancement**, and ties go to the
   simpler architecture.

This file is retained rather than deleted so the sequence that was
abandoned, and the reason, remain legible.
